בשפה פשוטה: מה קרה היום

פתחנו ריפו git משלו לפרויקט ופרסמנו אותו ב-GitHub. התקנו את כל ספריות ה-ML והשרת לסביבת AI_dev ונעלנו גרסאות. כתבנו שרת FastAPI מינימלי שעונה ב-/health "אני חי, זו הגרסה שלי, זה ה-commit שלי". חיברנו GitHub Actions שמריץ linter ובדיקות על כל push, ו-Railway שבונה ופורס מ-main. הכתובת החיה: funneliq-production-4b63.up.railway.app.

מה נבנה

  • ריפו: github.com/DorKatzav/funneliq (ציבורי). קומיט בסיס עם הברייף, הדאטה והתכנון; PR #1 עם השלד; PR #2 תיקון קטן לשער. תיקיית הקורס מתעלמת מהתיקייה הזו ב-.gitignore.
  • שרת: app/main.py עם /health (סטטוס, גרסה, commit, uptime), /api/config (רק ערכים ציבוריים: URL ו-anon key), ו-/ שמפנה לדף סטטי. app/config.py קורא הגדרות מהסביבה; מפתח ה-service בכוונה לא קיים שם.
  • בדיקות: ארבע ב-tests/test_api.py: שדות ה-health, ש-config לא חושף כלום מעבר לציבורי, ההפניה, והדף הסטטי.
  • CI: .github/workflows/ci.yml: התקנה ← ruff ← pytest, על כל push ו-PR.
  • Railway: railway.json (Nixpacks, uvicorn על $PORT, healthcheck ב-/health), runtime.txt = Python 3.11, משתני סביבה placeholder ל-Supabase.
  • שער: scripts/gate.py --m 0: pytest, ruff, סריקת סודות ב-git, ריצת Actions אחרונה על main, ו-health חי.
  • תיעוד: README עם badge ו-URL חי, .env.example, requirements.txt נעול.

שלוש הפתעות ומה למדנו

1. libomp "מותקן" אבל לא באמת

הבדיקה הראשונית של Homebrew הטעתה (הפקודה הצליחה גם כשהחבילה חסרה). xgboost ו-lightgbm קרסו בייבוא עד brew install libomp. הלקח: לבדוק את קובץ ה-dylib עצמו, לא את קוד היציאה של הפקודה. תועד ב-README.

2. סורק הסודות תפס את עצמו

הביטוי הרגולרי שמחפש service_role נמצא בתוך gate.py, אז הסריקה "מצאה סוד" בקובץ שלה. תוקן ב-PR #2: הסקריפט מוחרג מהסריקה של עצמו. לקח קטן על בדיקות שבודקות את עצמן.

3. הדומיין הראשון ב-Railway היה של מישהו אחר

הכתובת funneliq-production.up.railway.app החזירה אפליקציה של משתמש אחר (פרוטוטייפ בפורטוגזית). דומיינים ב-Railway גלובליים, ולכן הדומיין האמיתי קיבל סיומת: -4b63. הלקח: תמיד להעתיק מהפאנל Networking, לא להקליד מהזיכרון.
